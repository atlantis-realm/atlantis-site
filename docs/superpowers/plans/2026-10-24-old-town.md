# Old Town and the Lantern Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the island-and-temple city centre with Old Town and the Lantern. Old Town has a hero-aligned central grid round a square, patchwork culture quarters out to the first ring canal, and civic landmarks. The Lantern is generated, and the plan, the planner and the Blender scene all agree.

**Architecture:** Everything is generated in `citygen.js`. A new district type `oldtown` replaces `genTowers` for district `core`. It emits lots, prims and plan-drawable records (`o.lantern`, `o.quarters`, `o.squares`). The planner inlines the same file. `build_city.py` builds the prims, hides the hand-built temple and gains an emissive material for the Lantern's heart.

**Tech Stack:** Node 24 (CommonJS, `node:test`) for the generator; Blender 5.2 Python (`bpy`, through the Blender MCP) for the build; plain HTML/JS for the planner (published artifact).

**Spec:** `docs/superpowers/specs/2026-10-24-old-town-design.md`

All generator paths are under `concept-assets/city/generators/` (abbreviated `gen/`), in the clone `/run/media/dracky/e97d0aa9-5c45-460a-a682-b57cd6302030/Projects/atlantis-site-fork` on branch `wip-city`.

## Global Constraints

- Single source: every Old Town shape comes from `citygen.js`, and nothing in Old Town is hand-modelled.
- Seeded randomness only: `rng(key)` with keys starting `core|…`. Never `Math.random`.
- Keep ids `core` (district), `island` and `inner_water` (rings), `scene.temple` and `terrain.templeLift`. `makeTerrain`, the CLI and `build_city.py` regrade depend on them. Only user-facing labels change.
- New `MAT` keys are appended at the end of `MAT` in `build_city.py`, because the material index is the key's position. Every generated object's `coll` must be a `COLL` key. The Lantern uses `core`.
- No user-facing text says "island", "temple", "spire", "Circular Manhattan" or "Sable Heights".
- `citygen.js` must default every new setting, because the planner's store doc can predate them.
- Values from the spec: grid block 40–50 (default 46), street 10–12 (default 12), square ≈100 m, grid towers 120–220 m, band towers 200–300 m, landmarks 25–80 m, quarters 12–18 (default 15), quarter blocks 30–46 m, Lantern ≈500 m above the square, base 50–70 m (default 60), heart 40 %–80 % of the height, heart top ≥ 60 m above the tallest Old Town roof, second ring avenue off.
- Commit locally on `wip-city` at the end of each task (the user asked for this during alignment); never push. `.blend` files go through Git LFS.
- Run tests from `gen/` with `node --test "test/*.test.js"`. Plain `node --test test/` fails on Node 24, and bare `node --test` would also run `test/helpers.js` as a test. The helpers stay at `test/helpers.js`.
- Tests call real `citygen.js` functions, never copies. Each task's Interfaces block lists what it adds to the `CityGen` export list (the `return {…}` at the end of the IIFE).
- Old Town is built in a fixed order in `genOldTown`: ground and Lantern, then collect grid and quarter **blocks** (`{key, poly, zone, …}`), then assign landmarks to blocks by key, then build towers on the blocks left over.

## Review Focus

1. **An older store doc without the new keys.** If `core` lacks `grid`, `quarters`, `heights`, `lantern`, `landmarks` or `second_avenue`, `generate()` must still build Old Town from defaults and never throw (test in Task 1).
2. **Second avenue switched back on.** With `second_avenue: true`, the 350 avenue returns, the quarters stop either side of it, and skywalks return to two spines with rungs (tests in Tasks 1, 5 and 7).
3. **Different spoke count or rotation** (`spokes.count` 5 or 8, `offset_deg` 15). The grid still aligns to the hero bearing, quarter seams follow the spokes, and no block sits in a spoke corridor (test in Task 5).
4. **Lantern set lower than the towers** (`lantern.height` 300). Every Old Town top stays ≤ the cap and a warning names the cap. No lot city-wide outranks the heart top (test in Task 4, once towers exist).
5. **A culture list that doesn't fit** (`quarters.cultures` shorter than `count`, or an unknown id). Missing or unknown entries fall back to the seeded pick, and nothing throws (test in Task 5).

### Task 6: Landmarks

**Files:**
- Modify: `gen/citygen.js` (new `oldTownLandmarks`, `genOldTown`)
- Test: `gen/test/landmarks.test.js`

**Interfaces:**
- Consumes: the grid blocks and square (Task 4), the quarter blocks (Task 5), `building`, `roofTop`, culture styles, `assertUnderCap`.
- Produces:
  - `oldTownLandmarks(plan, d, blocks, square, hero, R) -> [{kind, label, keys, culture}]`, where `blocks` is the combined grid and quarter block list and `keys` lists the claimed block keys (one, except the parliament's two). Fragment blocks are never claimed.
  - **Exports added to `CityGen`:** `oldTownLandmarks`.
  - `genOldTown` order becomes: collect blocks → `oldTownLandmarks` → build landmarks on claimed keys → build towers on every other block.
  - Kinds:
    - `parliament`, on the far side of the square from the hero avenue (bearing `hero.a + 180°`). It claims the two square-facing blocks either side of the hero axis and merges them across the axis street, which stops at it. So it sits on the axis and closes the view straight down the hero avenue;
    - `exchange`, on the square-facing block beside the parliament (the next block along the square's far edge);
    - `courts`, on the square-facing block at hero − 90°;
    - `embassy` × `landmarks.embassies`, in quarter blocks, one per distinct culture first;
    - `guild` × `landmarks.guild_halls`, spread over the quarters.
  - Massing: one broad mass over ~85 % of the block, with a 4–6 m colonnade or forecourt edge facing the street or square. The **eave** height is uniform in `heights.landmark`.
    - Parliament and exchange also get a dome or drum (a `loft`) rising at most 20 m above the eave, and still under the cap.
    - Embassies and guild halls use their culture's `roofs` mix through `pickRoof`/`roofTop`.
